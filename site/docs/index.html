INTEGRATION · 0.7.4

DeviceTrust 接入手册

App 负责采集和签名上报，所有判断都在服务端完成。业务后端用应用密钥查询设备环境和业务风险，结论不经过 App。

01 / 接入准备

入口地址
工作台https://devicetrust-console.lingzidev.com
业务与上报 APIhttps://devicetrust-sdk-api.lingzidev.com
版本Android SDK 0.7.4 / Android 7.0+ / 四种 ABI
  1. 在“应用管理”创建应用，包名填写 Android applicationId。
  2. 保存创建时展示的应用 ID（appId，公开）与应用密钥（appKey，只展示一次，只放在业务后端）。
  3. 在“接入保护”填写 APK 签名证书 SHA-256（apksigner verify --print-certs app.apk）。平台据此比对签名并核对硬件证明。
  4. 业务后端实现 POST /device/prepare，见下文。
  5. 策略先用观察模式评估风险；确认业务处置已接入后再切换执行模式。
名称说明
deviceIdApp 安装的设备密钥登记后签发，同一 App 内稳定；不能作为登录或授权凭据
linkId同一台手机在你多个 App 中的设备归为一组
eventId业务后端生成的请求唯一 ID，持久保存以支持重试
reportId一次签名上报，App 上传后得到，交回业务后端查询

02 / Android SDK

下载 SDK 包，将 sdk 与 sdk-secure 的 aar 放入 app/libs。可选模块独立引入；安全模块包含已经混淆的原生库。

// app/build.gradle
dependencies {
  implementation files('libs/sdk-0.7.4.aar')
  implementation files('libs/sdk-secure-0.7.4.aar')
  // 可选：sdk-environment、sdk-rootbeer
}

启动登记

用户同意后，在后台线程初始化。登录前即可取得设备 ID；后续启动复用密钥并更新档案。

DeviceTrustClient.Config config = new DeviceTrustClient.Config(
    appId, businessUrl, pins);
JSONObject initialized = DeviceTrustClient.initialize(
    context, config, true, null);
String deviceId = initialized.getString("deviceId");

SDK 调用 {businessUrl}/device/prepare，请求体为 appId、installationId、keyId。业务后端代为申请 device_init（keyId 非空时为 device_refresh）挑战，返回 appId、platformUrl 和完整 challenge。这个公开入口只登记设备，不发放业务授权，需要限流。

关键业务上报

String keyId = SecureReporter.keyId(context, appId);
// 把 keyId 交给业务后端，取得绑定本次请求的 challenge
JSONObject report = DeviceTrust.collect(context,
    new DeviceTrust.Options(appId, true), true);
ResourceCollector.collect(context, report, true);
JSONObject result = SecureReporter.upload(
    context, api, pins, challenge, report);
String reportId = result.getString("reportId");
// reportId 交回业务后端查询结论

模拟点击识别

在 Activity 中记录触摸事件，平台据此识别脚本、按键精灵、无障碍手势和 input 命令注入的点击。

@Override public boolean dispatchTouchEvent(MotionEvent event) {
    TouchAudit.record(event);
    return super.dispatchTouchEvent(event);
}

基站、定位相关校验需要 App 取得定位权限后调用 EnvironmentCollector.collect(..., CELL, LOCATION)；未授权时这些规则不参与评分。

pin 为 API 证书 SPKI 的 SHA-256/Base64；证书公钥轮换前需先发布包含新旧 pin 的版本。SDK 会采集 ANDROID_ID、固定名单内风险应用是否安装（不读取应用列表）、无障碍状态和本机监听端口号，请在隐私政策中写明“用于安全风控”。

03 / 整体流程

用户发起登录、注册、领券、支付
  App ──► 业务后端：认证账号，生成 eventId、requestHash
          业务后端 ──► POST /v1/challenges（绑定账号、eventId、requestHash）
  App 采集并上报 ──► /v1/secure ──► reportId
  App ──► 业务后端：提交 reportId
          业务后端 ──► POST /v1/verdicts   查询设备环境
                   └─► POST /v1/events     评估业务事件（可选）
          按结论放行、加验证或拒绝

所有后端接口使用 Authorization: Bearer <appKey>。挑战 3 分钟有效、只能使用一次，并绑定账号、eventId 与 requestHash，偷来的报告无法挪用到别的账号或请求。

POST /v1/challenges
{
  "appId": "APP_ID",
  "eventId": "login-20261116-0001",
  "accountId": "u_10086",
  "type": "login",
  "clientIp": "203.0.113.10",
  "context": {"requestHash": "REQUEST_SHA256"},
  "keyId": "App 传来的 keyId，首次为空"
}

requestHash 是后端对方法、路径、账号和完整业务参数计算的 SHA-256，不能接受 App 传来的值。把响应原样交给 App。

04 / 查询设备环境

拿到 App 交回的 reportId 后查询。eventId、accountId 必须与申请挑战时一致，否则返回 403；报告超过 15 分钟返回 410。

POST /v1/verdicts
Authorization: Bearer <APP_KEY>

{"appId": "APP_ID", "reportId": "REPORT_ID",
 "eventId": "login-20261116-0001", "accountId": "u_10086"}
{
  "deviceId": "…", "linkId": "…", "keyStatus": "active",
  "riskScore": 85, "riskLevel": "high",
  "envScore": 85, "businessScore": 0,
  "factors": [
    {"code": "boot_state_spoofed", "points": 40, "source": "client"},
    {"code": "network_interface_mismatch", "points": 30, "source": "client"}
  ],
  "app": {"package": "com.example.app", "signer": "matched",
          "attestation": "none", "issue": "boot_unlocked"},
  "linked": {"devices": 1, "apps": 1, "maxRiskScore": 90, "highRisk": 1},
  "observedIp": "113.87.130.104",
  "reportedAt": "2026-11-16T10:00:00Z"
}
字段含义
riskScore / riskLevel0–100，等于 max(envScore, businessScore)；low < 30 ≤ medium < 70 ≤ high
envScore本次上报的设备环境分
businessScore该设备 7 天内业务事件的最高分
factors命中的规则，见规则代码
keyStatusactive；revoked 表示已在工作台停用
app.signermatched 一致；mismatch 不符（疑似重打包）；unknown 未上报；unconfigured 未填写证书
app.attestationtee / strongbox 表示硬件确认包名、签名且启动链锁定；none 表示未通过
app.issue硬件证明未通过的原因：boot_unlocked、app_mismatch、revoked、unverified、keystore_failed（设备 Keystore 无法生成证明，仅未要求硬件证明时出现）
linked这台手机在你其他 App 中的设备数、应用数、最高风险分和高风险设备数

建议：high 时拒绝或要求短信、人脸等更强核验；medium 时加验证；app.signer 为 mismatch 或 app.issue 为 app_mismatch 时直接拒绝；linked.highRisk > 0 表示这台手机在别的 App 中出现过高风险。

按设备 ID 查询历史

POST /v1/devices/query
{"appId": "APP_ID", "deviceId": "DEVICE_ID"}

返回这台设备最近一次上报的结论，格式相同。它只是历史档案，不能证明设备此刻在场；实时请求请用 /v1/verdicts。

05 / 业务事件评估

需要多账号、同设备集中注册、重复领取、支付工具轮换等业务维度风险时提交事件。账号、类型、IP 与 context 必须与挑战一致。

POST /v1/events
{
  "appId": "APP_ID",
  "eventId": "registration-20261111-001",
  "reportId": "REPORT_ID",
  "accountId": "ACCOUNT_ID",
  "type": "register",
  "clientIp": "203.0.113.10",
  "context": {"requestHash": "REQUEST_SHA256"}
}

type 为 register、reward、payment 或自定义类型。营销 context 使用 campaignId、recipientId；支付使用 orderId、paymentMethodId、amountMinor、currency，金额按最小货币单位。响应包含 score、action（observe、verify、hold）、mode、reasons 与策略版本。

06 / 应用身份校验

同一个 appId 只应由你自己签名的 App 使用。平台从两个层面判断：

  1. 签名比对（每次上报）：SDK 上报 APK 签名摘要，与“接入保护”中的证书比对，不一致命中 app_signature_mismatch。这一层由 App 自报，被 Hook 时可能伪造。
  2. 硬件证明（设备登记时）：SDK 生成密钥时总会附带平台挑战，Android Keystore 签发证书链。平台用 Google 根证书和每日更新的吊销列表验证证书链，读取硬件写入的包名、签名和启动状态。包名或签名不符、证书吊销（如泄露的 keybox）、Bootloader 未锁定分别计分；全部通过时 app.attestation 为 tee 或 strongbox。

默认情况下证明未通过只计分，不拒绝上报。在“接入保护”开启“硬件证明”后，未通过的设备会被直接拒绝，适合支付等高风险业务；开启前应先在目标机型上验收。

07 / 跨应用设备关联

每个 App 有各自的设备密钥，所以 deviceId 按 App 区分。平台另外计算 linkId，把同一台手机在你多个 App 中的设备归为一组：

依据条件
同一开发者设备标识各 App 使用同一个签名证书。Android 8 起 ANDROID_ID 按签名证书和用户隔离，同一签名的 App 在同一台手机上读到相同的值。
同一次开机硬件参数一致，且开机时刻相差不超过 2 秒。不依赖签名，两个 App 需在同一次开机期间上报过。

关联建立后会保存，手机重启或 App 重装后依然有效：重装后得到新的 deviceId，linkId 不变。工作台“设备 → 关联与轨迹”列出同一台手机在其他 App 中的设备。verdict 只给出 linked 汇总，不会把其他 App 的 deviceId 透露给当前后端。

关联需要 SDK 0.7 及以上。关联依据来自客户端，可能被改机工具篡改，只能作为风险线索，不能作为身份证明。

局域网聚集（工作室识别）

SDK 0.7.4 起上报内网地址、网段、网关和 DNS，工作台可按内网 IP 搜索设备。平台按“路由器 BSSID”（需定位权限）或“出口 IP + 内网网段 + 网关”判断同一局域网。老设备申请挑战时，响应里的 lanTargets 列出最近 2 小时同网的其他 SDK 设备，SDK 只探测其中位于本机网段内的地址（ICMP 可达、ADB 5555 端口），不扫描其他设备。后端须把挑战响应原样交给 App。

结果规则
24 小时内同一局域网 ≥ 5 台手机lan_device_cluster，20 分
同网设备开放 ADB 无线调试lan_adb_peers，30 分
网关可达但同网设备全部不可达疑似 AP 隔离，不计分，聚集规则照常生效

verdict 新增 lan.devices（24 小时内同网的其他手机数）和 lan.adbPeers。公司、酒店等公共 Wi-Fi 下的聚集属正常现象，宜与其他线索一起判断。隐私政策需写明会采集内网地址并检测同网设备是否可达。

08 / 后端示例

Go

guard := businessguard.Client{BaseURL: api, AppID: appID, AppKey: appKey}
verdict, err := guard.Verdict(ctx, reportID, eventID, accountID)
if err != nil { return err } // 失败不当作“通过”
if verdict.RiskLevel == "high" || verdict.App.Signer == "mismatch" {
    // 拒绝或加验证
}

Java 11+

HttpRequest request = HttpRequest.newBuilder(URI.create(api + "/v1/verdicts"))
    .header("Authorization", "Bearer " + appKey)
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString(body)) // appId、reportId、eventId、accountId
    .build();
HttpResponse<String> response = HttpClient.newHttpClient()
    .send(request, HttpResponse.BodyHandlers.ofString());
if (response.statusCode() != 200) throw new IllegalStateException(response.body());

Node.js 18+

const response = await fetch(`${api}/v1/verdicts`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${appKey}`, 'Content-Type': 'application/json' },
  body: JSON.stringify({ appId, reportId, eventId, accountId }),
})
if (!response.ok) throw new Error(`${response.status} ${await response.text()}`)
const verdict = await response.json()

请求失败时不要把设备当作安全处理，应按业务的失败策略拒绝或要求重试。Go 组件 businessguard 在 SDK 包 server 目录中。

10 / 连接实际处置

执行模式下，核验或暂缓事件须先取得批准。业务服务应在完成真实核验后提交结果，或交由工作台审批。

POST /v1/decisions/resolve
{"appId":"APP_ID","eventId":"EVENT_ID",
 "resolutionId":"VERIFY_RESULT_ID","status":"approved"}

POST /v1/decisions/claim
{"appId":"APP_ID","eventId":"EVENT_ID",
 "operationId":"BUSINESS_OPERATION_ID","requestHash":"REQUEST_SHA256"}

POST /v1/executions
{"appId":"APP_ID","eventId":"EVENT_ID",
 "operationId":"BUSINESS_OPERATION_ID","token":"CLAIM_TOKEN",
 "receiptId":"RECEIPT_ID","status":"succeeded",
 "reference":"BUSINESS_REFERENCE"}

claim 的 token 与 expiresAt 是执行凭据，首次领取限事件或批准后 5 分钟内。业务必须检查到期时间，在自己的数据库按 operationId 原子幂等提交。支付真实回调通过 /v1/outcomes 回流，字段见 SDK 包 docs/business-risk.md。

11 / 排查与重试

状态处理
400请求格式或必填字段错误，查看 error。
401检查应用密钥。
403报告属于其他应用或其他业务请求、密钥已停用、要求硬件证明但未通过。
404应用、报告或设备不存在。
409同一 ID 已用于不同内容，修正幂等数据，不能覆盖旧记录。
410挑战或报告过期，让 App 重新采集。
TLS / pin mismatch核对服务域名、证书链与 SPKI，不能关闭证书验证。

服务端原始错误会保留。记录 eventId、reportId、发生时间和完整错误，排查时不要附带应用密钥或用户敏感信息。
